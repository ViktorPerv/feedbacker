# Feedbacker — окружение Docker

Инфраструктурный репозиторий сервиса **Feedbacker** — сбора и показа отзывов
клиентов (self-hosted версия в духе [testimonial.to](https://testimonial.to)).

Здесь живут Docker Compose, образы PHP и Go, конфиг Nginx, Makefile и общие
значения окружения. Код приложения — в двух соседних репозиториях.

```
feedbacker/
├── docker/          ← этот репозиторий (инфраструктура)
├── laravel/         ← приложение (Laravel 13 + Inertia + Vue 3)
└── go-widget/       ← публичный сервис виджетов (Go)
```

---

## Требования

| Инструмент | Версия | Примечание |
|------------|--------|-----------|
| Docker Desktop | 4.x+ | на Windows — с бэкендом WSL 2 |
| GNU Make | 3.81+ | `make` внутри WSL / macOS / Linux |
| Git | любая | |

Больше на хосте ничего ставить не нужно — PHP, Node, PostgreSQL и Redis
работают в контейнерах.

> **Пользователям Windows:** выполняйте команды **внутри WSL**, а не в
> PowerShell. В Docker Desktop должна быть включена интеграция с вашим
> дистрибутивом WSL.

## Быстрый старт

### 1. Клонируйте три репозитория рядом

```bash
mkdir -p ~/feedbacker && cd ~/feedbacker

git clone <docker-repo-url>  docker
git clone <laravel-repo-url> laravel
git clone <go-repo-url>      go-widget
```

Раскладка каталогов важна: `docker/docker-compose.yml` монтирует `../laravel`
и собирает `../go-widget`.

### 2. Создайте локальный файл окружения

```bash
cd docker
cp .env-common .env
```

`.env-common` хранит значения по умолчанию и лежит в git; `.env` — ваш личный
и в git не попадает. Меняйте там доступы к БД, порты и токен GitHub.

### 3. Соберите и запустите стек

```bash
make up
```

Собираются образы PHP и Go, поднимаются девять сервисов. Первая сборка
занимает несколько минут — компилируются расширения PHP.

### 4. Подготовьте приложение

```bash
make env          # создать laravel/.env из .env.example и сгенерировать APP_KEY
make vendor       # composer install
make migrate      # создать схему БД
make seed         # создать админский аккаунт
make npm-install
make npm-build
make i18n         # залить переводы в БД (необязательно, но полезно)
```

### 5. Откройте приложение

| Адрес | Что там |
|-------|---------|
| http://localhost:8080 | Приложение (лендинг, кабинет) |
| http://localhost:8081/health | Проверка живости Go-сервиса виджетов |
| http://localhost:8025 | Mailpit — вся исходящая почта |
| http://localhost:9001 | Консоль MinIO (`minioadmin` / `minioadmin`) |

### Админский аккаунт по умолчанию

`make seed` запускает `RolePermissionSeeder`, а затем создаёт локального
администратора с ролью `admin`, беря значения из `laravel/.env`:

| Поле | Значение по умолчанию |
|------|----------------------|
| Email | `admin@feedbacker.test` |
| Пароль | `password` |

Поменяйте `ADMIN_EMAIL` / `ADMIN_PASSWORD` в `laravel/.env` до сидирования или
запустите `make seed` заново — оба сидера идемпотентны.

> Сидер предупреждает, если пароль всё ещё `password`. Никогда не выкатывайте
> в продакшен со стандартными доступами.

Можно и зарегистрироваться самостоятельно на http://localhost:8080/register —
это обычный путь пользователя, новые аккаунты автоматически получают роль `user`.

## Отзывы

### Сбор

У каждого пространства есть публичная страница сбора `/c/{slug}` — аккаунт не
нужен. Она отрисована в оформлении пространства (логотип, цвета, шрифт, текст
кнопки и благодарности) и спрашивает имя, необязательные должность, компанию и
почту, оценку от 1 до 5 и сам отзыв.

Отправленное всегда попадает в статус `pending`. Публично ничего не видно,
пока отзыв не одобрен.

| Маршрут | Метод | Примечание |
|---------|-------|-----------|
| `/c/{slug}` | GET | Публичная страница сбора |
| `/c/{slug}` | POST | Отправка — не чаще 10 запросов в минуту с одного IP |

Защита публичной формы:

- **Ловушка** — скрытое поле `website`. Если оно заполнено, отправка
  отбрасывается, но ответ всё равно выглядит успешным, чтобы бот ничему не
  научился.
- **Ограничение частоты** — `throttle:10,1` на POST-маршруте.
- **Поля под контролем сервера** — `status`, `is_featured`, `tags` и `space_id`
  никогда не берутся из тела запроса, поэтому отправитель не может
  самоодобриться или написать в чужое пространство.

### Модерация

Входящие — на `/spaces/{slug}/testimonials`. Список с вкладками по статусу
(все / на проверке / одобренные / отклонённые), поиском по имени автора, тексту
и компании, и фильтром по оценке.

Действия по каждому отзыву:

| Действие | Что происходит |
|----------|----------------|
| Одобрить | `status = approved`, проставляется `approved_at` |
| Отклонить | `status = rejected`, сбрасывается `is_featured` |
| В избранное | Переключает `is_featured` (влияет на порядок в стене) |
| Удалить | Удаляет запись |

Доступно владельцу пространства или любому аккаунту с правом
`testimonials.moderate.any` (роль `admin`).

### Модель данных

`Testimonial` принадлежит `Space` и удаляется каскадом. Статус — enum
(`App\Enums\TestimonialStatusEnum`), приведённый на модели, поэтому сохранить
недопустимое состояние невозможно. `tags` — колонка `json`, а не массив
PostgreSQL, чтобы та же схема работала в тестовой БД.

## Виджет и аналитика

### Встраивание

Одобренные отзывы отдаёт Go-сервис виджетов в виде самодостаточного скрипта.
Код вставки есть на странице пространства и на странице аналитики:

```html
<div data-feedbacker="your-slug"></div>
<script async src="http://localhost:8081/w/your-slug.js"></script>
```

Заглушка необязательна: если на странице нет элемента `[data-feedbacker]`,
виджет создаст его сам и добавит в `<body>`.

Всё рендерится внутри **shadow root**, поэтому CSS страницы-хозяина не
протекает внутрь, а CSS виджета — наружу. Вёрстка — адаптивная стена отзывов на
CSS-колонках, со звёздами, аватарами (с запасным вариантом из инициалов) и
меткой избранного.

> **Адрес скрипта.** Код вставки указывает на **сервис виджетов**, а не на
> приложение: `/w/…` отдаёт Go, а не Laravel. В продакшене оба обычно стоят за
> одним доменом, локально это разные порты. За это отвечает `WIDGET_PUBLIC_URL`.

### Живой пример на главной

Лендинг встраивает **настоящий виджет** из пространства `admin-space`, чтобы
посетитель видел работающий продукт, а не скриншот. Раздел появляется, только
если демо-виджет существует.

```bash
make artisan cmd="db:seed --class=DemoContentSeeder"
```

Сидер создаёт шесть одобренных отзывов и виджет-стену. Он идемпотентен, а
пространство для демонстрации задаётся через `WIDGET_DEMO_SPACE`.

Скрипт подключается из `onMounted`: буквальный тег `<script>` в шаблоне Vue
разобрался бы как скрипт самого компонента. Так выполняется ровно тот же путь
кода, что и на сайте клиента.

### Конструктор виджетов

У пространства может быть сколько угодно именованных виджетов, у каждого своя
вёрстка и фильтры — на `/spaces/{slug}/widgets`. Это то, что не выразить
параметрами в строке запроса: одно пространство даёт стену на главной, бейдж в
подвале и карусель на лендинге, каждое со своими настройками.

| Вёрстка | Что рисует |
|---------|-----------|
| `masonry` | Адаптивная сетка на CSS-колонках |
| `carousel` | Горизонтальная лента со стрелками |
| `single` | Один отзыв — для первого экрана или сайдбара |
| `badge` | Аватары, средний балл и число отзывов |

Фильтры задаются на каждый виджет: `featured_only` и `min_rating`. Правила
вёрстки важнее сохранённых значений там, где иначе нельзя: виджет `single`
всегда запрашивает ровно один отзыв, и именно избранный.

Каждый виджет получает публичный **токен** из 24 символов, и его адрес
встраивания обращается к виджету по этому токену:

```
http://localhost:8081/w/{space-slug}/{token}.js
```

Токен — никогда не UUID: он попадает в исходники чужих страниц. Он же неизменен
при редактировании, потому что смена сломала бы все страницы, где виджет уже
встроен.

Конструктор показывает **предпросмотр** выбранной вёрстки на демо-данных, так
что четыре варианта можно сравнить, ничего не публикуя.

### Видео-отзывы

Форма сбора принимает необязательную ссылку на видео, только `http` и `https`.
Бандл распознаёт YouTube, Vimeo и прямые файлы `.mp4`/`.webm`/`.ogg` и
проигрывает их в лайтбоксе внутри виджета; всё остальное открывается в новой
вкладке.

Загрузка собственных видео **не входит** в эту часть: хранилище ниже может
держать файлы, но интерфейса записи пока нет.

## Уведомления, теги и поиск

### Уведомления

Отправка отзыва ставит в очередь уведомление владельцу пространства. Именно в
очередь: запрос посетителя не должен ждать SMTP-рукопожатия, а сбой почты не
должен ломать его отправку — уведомление отправляется внутри защитного блока,
поэтому сломанный почтовик не может потерять отзыв.

Локально используется **Mailpit**: он перехватывает всё и показывает на
http://localhost:8025. SMTP-аккаунт не нужен.

```bash
docker compose logs -f queue-worker   # смотреть обработку заданий
```

| Переменная | Значение | Примечание |
|------------|----------|-----------|
| `MAIL_MAILER` | `smtp` | для всего, кроме локальной разработки, укажите реальный релей |
| `MAIL_HOST` / `MAIL_PORT` | `mailpit` / `1025` | |
| `QUEUE_CONNECTION` | `redis` | сервис `queue-worker` выполняет `queue:work` |

> Изменения окружения доходят до контейнера только при **пересоздании**. После
> правки `.env-common` нужен `docker compose up -d app` — рестарта недостаточно.

### Теги

Теги свободные, у каждого отзыва свои, хранятся в json. При сохранении они
нормализуются: обрезаются пробелы, приводится нижний регистр, убираются
дубликаты, максимум 10 тегов по 32 символа. Входящие показывают все
используемые теги со счётчиками, а фильтр по тегу — один клик.

`PATCH /testimonials/{id}/tags` принимает весь список целиком; `[]` очищает его.

> Пустые значения отбрасываются **до** валидации. Поле тега отдаёт `""` при
> очистке, `ConvertEmptyStringsToNull` превращает это в `null`, и правило
> `string` отклонило бы весь запрос из-за одной случайной записи — потеряв те
> теги, которые пользователь всё-таки ввёл.

### Полнотекстовый поиск

`testimonials.search_vector` — **генерируемая** колонка `tsvector` с GIN-индексом:
PostgreSQL пересчитывает её при записи, поэтому расхождение с данными
невозможно.

```sql
to_tsvector('simple',
    author_name || ' ' || author_title || ' ' || author_company || ' ' || content
)
```

Конфигурация `simple` выбрана осознанно. `english` стеммил бы английские слова,
но русские воспринимал бы как непрозрачные токены; `simple` только приводит к
нижнему регистру, поэтому все языки ведут себя одинаково. То стемминг-поведение,
которое пользователи реально замечают, закрывается **префиксным поиском**: поле
поиска превращает `embed` в `embed:*`, поэтому находится «embeds».

Условия соединяются по И, а результаты сортируются по `ts_rank`, а не по дате —
при поиске нужен лучший результат первым, а не самый свежий.

Запрос без пригодных токенов (только пунктуация) пропускает условие целиком:
`to_tsquery('')` — синтаксическая ошибка в PostgreSQL.

## Языки

Сейчас в поставке английский и русский. Каталог переводов живёт в **базе
данных**, поэтому формулировки правятся из приложения, а не деплоем.

### Откуда берётся строка

```
строка в БД  →  языковой файл  →  сам ключ
```

Файлы (`lang/{locale}/*.php`) остаются источником правды о том, *какие* ключи
существуют; в базе правится их текст. Ключ без записи — или запись с пустым
значением — откатывается на файл, поэтому новая строка может уехать до того,
как её кто-то перевёл, а удаление записи возвращает значение из файла, а не
обнуляет интерфейс.

Работают две части, и нужны обе:

| Часть | Зачем |
|-------|-------|
| `App\Translation\DatabaseLoader` | Читает строки и накладывает их поверх массива из файла |
| `App\Translation\DatabaseTranslator` | Транслятор Laravel запоминает каждую загруженную группу и за один запрос ни разу не спросит загрузчик повторно — сохранённый перевод оставался бы невидимым до следующего запроса |

### Выбор языка

Порядок разрешения в `App\Http\Middleware\SetLocale`:

1. сессия — явный выбор в переключателе
2. сохранённое предпочтение авторизованного пользователя
3. заголовок `Accept-Language` браузера
4. язык, помеченный как язык по умолчанию

`GET /locale/{code}` открыт и гостям, потому что публичная страница сбора тоже
должна читаться на любом языке. Выбор авторизованного пользователя ещё и
записывается в профиль, чтобы переехать в другой браузер.

### Каталог

**`/translations`** — доступен `admin` и роли **`translator`**.

Роль переводчика существует, чтобы каталог можно было вести, не давая доступа к
данным клиентов: у неё есть `translations.manage` и ничего больше, поэтому
переводчик не откроет пространство, не смодерирует отзыв и не тронет
пользователей.

| Возможность | |
|-------------|---|
| Полосы прогресса | Насколько переведён каждый язык относительно числа ключей в языке по умолчанию |
| Фильтры | Язык, группа, свободный поиск (по ключу **и** значению), «только непереведённые» |
| Импорт | `translations:import` затягивает языковые файлы — **аддитивно**, поэтому работа переводчика не затирается деплоем |
| Панель «другие языки» | На странице редактирования — как тот же ключ звучит в остальных языках |

**Идентичность перевода — это `(язык, группа, ключ)`, и она задаётся при
создании.** Редактирование переписывает текст и ничего больше.

Это сделано намеренно. Уникальность — забота времени создания: как только ключ
существует в обоих языках (обычное состояние после импорта), смена языка или
ключа у существующей записи означала бы переезд на место, которое уже занято
другой строкой. Поэтому страница редактирования показывает идентичность только
для чтения, а обновление игнорирует любую попытку её изменить — так коллизия
становится невозможной, а не просто отклоняемой.

Чтобы использовать другой ключ, создайте новую запись и удалите старую.

### Что переведено

Всё, что видит пользователь: лендинг, вход и регистрация, панель, пространства,
оформление, аналитика, конструктор виджетов, входящие с модерацией, профиль,
публичная страница сбора и сам каталог — **318 ключей интерфейса** на язык,
уходящих на фронтенд с каждым ответом Inertia.

За этим стоят группы фреймворка, которые остаются на сервере:

| Группа | Ключей | Примечание |
|--------|--------|-----------|
| `app` | 318 | интерфейс; единственная группа, уходящая в браузер |
| `validation` | 138 / 111 | правила, которые использует приложение, плюс общие |
| `passwords` | 5 | |
| `auth` | 3 | |
| `pagination` | 2 | |

Валидация переведена **частично** намеренно: правило без русской строки
откатывается на английский через `fallback_locale`, поэтому непереведённый
крайний случай читается по-английски, а не показывает сырой ключ. Имена полей
тоже переведены, поэтому сообщение звучит как «Поле «имя автора» обязательно
для заполнения», а не называет колонку.

> Формы множественного числа используют синтаксис `|` из Laravel и разрешаются
> на фронтенде через `useTranslations().tc()`, где реализовано русское правило
> 1 / 2–5 / остальное. Английские строки несут две формы, русские — три.

### Как добавить строку

1. Добавьте ключ в `lang/en/app.php` **и** в `lang/ru/app.php` — тест падает,
   если наборы ключей разойдутся.
2. Запустите `make i18n` — создаст записи и пересоберёт бандл.
3. Используйте: `t('group.key')` в Vue, `__('app.group.key')` в PHP.

```bash
make i18n                  # импорт + пересборка + очистка кешей
make i18n force=1          # ещё и перезаписать БД из файлов
make i18n prune=1          # ещё и удалить строки, чьих ключей больше нет
```

**Когда нужна пересборка.** Значения переводов живут в базе и разрешаются на
каждый запрос, поэтому правка формулировки видна после перезагрузки. Пересборка
нужна для изменений в шаблонах Vue — новый вызов `t()`, переименованный ключ,
новая страница, — потому что в бандл попадают вызовы, а не строки. `make i18n`
закрывает оба случая.

`--prune` нужен, чтобы каталог оставался честным после переименования ключа: без
него старая строка остаётся и переводчик видит записи, которые ничего не
отрисовывают. Он ограничен просканированными языками и группами, поэтому
`--group=auth` не снесёт остальной каталог.

### Никогда не называйте проп страницы так же, как общий

Inertia накладывает пропы страницы поверх общих, поэтому страница, передающая
свой `translations`, подменяет общую карту переводов — и каждый вызов `t()` на
ней отдаёт сырой ключ. Именно так каталог однажды уехал с непереведёнными
кнопками: его пропом был объект пагинатора.

Общие имена: `auth`, `flash`, `locale`, `locales`, `translations`. Каталог
передаёт свои строки как **`entries`**. Тест проверяет, что общая карта выживает
на каждой странице, и падает, если коллизию вернут.

## Объектное хранилище

Загрузки (логотипы пространств, аватары авторов) идут в S3-совместимое
объектное хранилище. MinIO поднимается в том же стеке, поэтому локальная
разработка не требует аккаунта AWS.

| Сервис | Контейнер | Порт | Примечание |
|--------|-----------|------|-----------|
| `app` | `feedbacker-app` | — | php-fpm |
| `queue-worker` | `feedbacker-queue` | — | `queue:work`, тот же образ, что `app` |
| `nginx` | `feedbacker-nginx` | 8080 | |
| `widget-server` | `feedbacker-widget` | 8081 | Go |
| `pgsql` | `feedbacker-pgsql` | 5432 | PostgreSQL 15 |
| `redis` | `feedbacker-redis` | 6379 | кеш и очередь |
| `mailpit` | `feedbacker-mailpit` | 8025 (UI), 1025 (SMTP) | перехватывает всю почту |
| `minio` | `feedbacker-minio` | 9000 (API), 9001 (консоль) | S3-совместимое |
| `minio-init` | `feedbacker-minio-init` | — | одноразовый: делает бакет публичным |

Консоль: http://localhost:9001 — `minioadmin` / `minioadmin`.

### Приложение не называет диск

Всё идёт через фасад `Storage` и `App\Support\Uploads`, а бэкенд выбирает
`FILESYSTEM_DISK`. Переход с MinIO на настоящий S3 или на локальную файловую
систему — это правка конфига, а не кода.

```bash
make minio-init     # (пере)применить политику бакета
make minio-shell    # mc и шелл внутри контейнера MinIO
make storage-link   # нужно только при FILESYSTEM_DISK=local
```

### Два адреса, и почему

`docker/.env-common` задаёт оба:

| Переменная | Значение | Кто использует |
|------------|----------|----------------|
| `AWS_ENDPOINT` | `http://minio:9000` | **контейнер приложения** загружает сюда |
| `AWS_URL` | `http://localhost:9000/feedbacker` | **браузер** грузит картинки отсюда |

Приложение обращается к MinIO по имени сервиса в compose; браузер это имя не
резолвит и ему нужен опубликованный порт. Перепутать их — получить ссылки,
которые прекрасно загружаются, а потом дают 404 на странице.

### Загрузки

| Маршрут | Поле | Кто |
|---------|------|-----|
| `POST /spaces/{slug}/logo` | `logo` | владелец пространства или `spaces.update.any` |
| `DELETE /spaces/{slug}/logo` | — | то же |
| `POST /testimonials/{id}/avatar` | `avatar` | владелец или `testimonials.moderate.any` |
| `DELETE /testimonials/{id}/avatar` | — | то же |

Валидация (`UploadImageRequest`):

- **PNG, JPG или WebP**, до **2 МБ**, не более **2400×2400** пикселей
- Правило размеров не косметика: decompression bomb проходит проверку веса, но
  не эту, а для чтения размеров GD должен быть собран с поддержкой WebP
- **SVG отклоняется намеренно** — SVG может нести скрипт, а эти файлы отдаются
  из бакета, который браузер загружает напрямую

Файлы лежат по детерминированному пути (`spaces/{id}/logo.{ext}`), поэтому замена
логотипа удаляет предыдущий файл с любым расширением. В колонке остаётся
**URL**, поэтому вставленная ссылка и загрузка взаимозаменяемы.

Бакет настроен на **анонимное скачивание**, а не на presigned-ссылки: логотипы и
аватары показываются на публичных страницах сбора и в виджетах, то есть являются
публичными активами. Подписанные ссылки истекали бы и ломали встроенные стены.

> **Известный пробел:** удаление пространства убирает его строку, но оставляет
> объекты в бакете. Удалять файлы внутри транзакции хуже, чем оставить сироту,
> поэтому уборка — задача фонового джоба, который вычищает объекты без владельца.

### Настройка встраивания

Параметры передаются в строке запроса, поэтому одно пространство может питать
несколько по-разному настроенных стен, не трогая базу:

| Параметр | По умолчанию | Примечание |
|----------|--------------|-----------|
| `theme` | `light` | `light` или `dark` |
| `columns` | `3` | 1–6 |
| `limit` | `50` | 1–200 |
| `accent` | цвет из оформления | `#RGB` или `#RRGGBB` |
| `font` | из оформления | должен быть простым набором шрифтов |
| `heading` | `What our customers say` | не длиннее 120 символов |
| `ratings` | `1` | `0` скрывает звёзды |
| `footer` | `1` | `0` скрывает подпись |

```
/w/acme-inc.js?theme=dark&columns=2&limit=12&accent=%23112233
```

Всё отсутствующее или выходящее за границы откатывается к значению по умолчанию,
а `accent` и `font` проверяются, потому что подставляются в CSS-объявление.

### Маршруты сервиса виджетов

| Метод | Путь | Назначение |
|-------|------|-----------|
| `GET` | `/health` | Живость; пингует PostgreSQL |
| `GET` | `/w/{slug}.js` | Встраивание на всё пространство (`.js` необязателен) |
| `GET` | `/w/{slug}/{token}.js` | Сохранённый виджет, настроенный своей строкой |
| `GET` | `/api/public/spaces/{slug}` | Публичная проекция пространства |
| `GET` | `/api/public/spaces/{slug}/wall` | Одобренные отзывы; `?limit=`, `?featured_only=`, `?min_rating=` |
| `GET` | `/api/public/spaces/{slug}/testimonials` | Псевдоним `/wall` |
| `GET` | `/api/public/widgets/{token}` | Стена сохранённого виджета, фильтры применены на сервере |
| `POST` | `/api/track/view` | Записать показ |
| `POST` | `/api/track/click` | Записать клик по карточке |

`{slug}` в `/w/{slug}/{token}.js` — украшение для читаемости, но он обязан
совпадать с токеном: устаревший код, указывающий на чужое пространство,
отклоняется, а не молча отдаёт отзывы другого аккаунта.

`author_email` не раскрывается никогда — он собирается на странице сбора и
остаётся внутри приложения.

### Кеширование и ограничение частоты

Ответы `/wall` кешируются **в процессе** на 60 секунд. Для одного экземпляра это
быстрее сетевого похода в Redis и не требует лишней зависимости; плата — 
одобренный отзыв может появиться с задержкой до минуты. Мгновенная инвалидация
потребовала бы общего счётчика версий у двух сервисов — это естественный
следующий шаг при горизонтальном масштабировании.

Маршруты трекинга ограничены **60 запросами в минуту с одного IP** счётчиком с
фиксированным окном. Чтения не ограничиваются — показы виджета это ровно тот
трафик, который обязан оставаться быстрым. IP, присланный клиентом,
игнорируется; записывается только адрес соединения.

### Аналитика

Панель и каждое пространство показывают показы, клики и долю кликов за окно в
7, 30 или 90 дней. Страница аналитики пространства на
`/spaces/{slug}/analytics` добавляет столбчатую диаграмму по дням, самые
кликабельные отзывы и код вставки.

Агрегация живёт в `App\Support\Analytics` и всегда принимает коллекцию
идентификаторов пространств, поэтому область определяет вызывающий: участник
передаёт свои пространства, администратор — все.

> Аналитика только дописывается. `widget_views` сохраняет строку при удалении
> отзыва (ссылка обнуляется); `testimonial_clicks` удаляется каскадом.

## Роли и права

Авторизация построена на
[spatie/laravel-permission](https://spatie.be/docs/laravel-permission). Сейчас
в поставке три роли:

| Роль | Кому выдаётся | Назначение |
|------|---------------|-----------|
| `admin` | `AdminUserSeeder` (локальная разработка) | Надзор по всем аккаунтам |
| `translator` | вручную | Ведёт каталог переводов, без доступа к данным клиентов |
| `user` | автоматически при регистрации | Обычный владелец аккаунта |

Права следуют соглашению `<resource>.<action>[.scope]`. Суффикс `.any` отмечает
надзор поверх аккаунтов; всё остальное регулируется владением в политике и права
не требует.

| Право | `admin` | `translator` | `user` |
|-------|:-------:|:------------:|:------:|
| `spaces.view.any` | ✅ | — | — |
| `spaces.update.any` | ✅ | — | — |
| `spaces.delete.any` | ✅ | — | — |
| `testimonials.moderate.any` | ✅ | — | — |
| `users.manage` | ✅ | — | — |
| `translations.manage` | ✅ | ✅ | — |

Как это разрешается в `SpacePolicy`:

| Возможность | Владелец | `admin` | Другой `user` |
|-------------|:--------:|:-------:|:-------------:|
| Область `spaces.index` | свои пространства | **все пространства** | свои пространства |
| `view` / `update` / `delete` | ✅ | ✅ | 403 |
| `moderateTestimonials` (входящие) | ✅ | ✅ | 403 |

Владения достаточно для операций над своими ресурсами, поэтому аккаунт, у
которого отозвали роль, всё равно сохраняет доступ к своим данным.

Контроллеры передают разрешённые возможности на фронтенд, поэтому интерфейс
ничего не угадывает: `spaces.index` отправляет объект `can: { update, delete }`
для каждого пространства, `spaces.show` — `can: { update, delete }`.

### Как добавить роль или право

1. Добавьте случай в `app/Enums/RoleEnum.php` или `app/Enums/PermissionEnum.php`.
2. Выдайте его в `RoleEnum::permissions()`.
3. Запустите `make seed` — сидер идемпотентен.

Enum держит имена в одном месте, поэтому опечатка становится ошибкой времени
сборки, а не молчаливым `PermissionDoesNotExist` в рантайме.

## Конфигурация

Три файла, три задачи:

| Файл | В git | Назначение |
|------|-------|-----------|
| `docker/.env-common` | да | Значения Docker по умолчанию: доступы к БД, порты, клиент Redis, UID/GID |
| `docker/.env` | нет | Ваши локальные переопределения |
| `laravel/.env` | нет | Конфиг приложения, включая `APP_KEY` и админский аккаунт |

`APP_KEY`, `APP_ENV` и `APP_DEBUG` намеренно живут **только** в `laravel/.env`.
Dotenv в Laravel никогда не перезаписывает уже существующую переменную
окружения, поэтому их передача из Compose молча затеняла бы конфиг приложения.

### Переменные, которые чаще всего меняют

| Переменная | По умолчанию | Где |
|------------|--------------|-----|
| `DB_USERNAME` / `DB_PASSWORD` | `feedbacker` / `secret` | `docker/.env` |
| `DB_DATABASE` | `feedbacker` | `docker/.env` |
| `APP_PORT` | `8080` | `docker/.env` |
| `WIDGET_PORT` | `8081` | `docker/.env` |
| `WIDGET_PUBLIC_URL` | `http://localhost:8081` | `docker/.env` — адрес сервиса виджетов для браузера |
| `WIDGET_DEMO_SPACE` | `admin-space` | `docker/.env` — какое пространство показывает лендинг |
| `GITHUB_TOKEN` | пусто | `docker/.env` — для приватных пакетов Composer |
| `ADMIN_EMAIL` / `ADMIN_PASSWORD` | `admin@feedbacker.test` / `password` | `laravel/.env` |

## Тестирование

```bash
make test               # клонировать схему, затем прогнать набор
make test_feature       # только Feature
make test_unit          # только Unit
make test_db            # создать тестовую БД, если её нет
make test_db_migration  # клонировать структуру из БД разработки
make test_db_drop       # удалить тестовую БД
make test-db-shell      # psql в тестовую БД
```

### Как устроена тестовая база

Набор работает против **PostgreSQL**, а не SQLite — тот же движок, что в
продакшене, поэтому json-колонки, семантика `LIKE` и ограничения ведут себя
одинаково.

Тестовая база (`feedbacker_test`) **не строится миграциями**. Её схема
клонируется из базы разработки:

```
make migrate            # разрабатываем схему в `feedbacker`
make test_db_migration  # pg_dump --schema-only → `feedbacker_test`
```

`make test` сначала запускает `test_db_migration`, поэтому схема не может
разойтись с миграциями, которые построили базу разработки. После добавления
миграции достаточно `make migrate && make test`.

Поскольку схема уже построена, тесты **не мигрируют**. Каждый тест выполняется
внутри транзакции (`DatabaseTransactions`), которая откатывается после, поэтому
записанное одним тестом не видно следующему. `Tests\TestCase` проверяет наличие
схемы и, если её нет, падает с понятным сообщением, предлагающим запустить
`make test_db_migration`.

### Фикстуры

Тестовые данные берутся из `tests/Fixtures/TestFixturesSeeder.php` — один
канонический набор, общий для всех тестов:

| Аккаунт | Роль | Пространства |
|---------|------|--------------|
| `admin@feedbacker.test` | `admin` | нет (только надзор) |
| `owner@feedbacker.test` | `user` | `acme-inc` (активно), `globex` (закрыто) |
| `stranger@feedbacker.test` | `user` | `initech` |
| `translator@feedbacker.test` | `translator` | нет |

В `acme-inc` четыре отзыва — Alice (одобрен и в избранном), Bob (одобрен), Carol
(на проверке) и Dave (отклонён), — поэтому фильтрам по статусу, счётчикам и
потокам модерации есть с чем работать. Их `created_at` намеренно разнесены по
дням: схема хранит время с точностью до секунды, поэтому записи, созданные в
одну секунду, сравниваются вничью и проверки порядка были бы недетерминированы.

Тесты обращаются к набору через типизированные помощники, а не создают свои
записи:

```php
$this->actingAs($this->fixtureOwner())
    ->get(route('spaces.show', $this->fixtureSpace()->slug))
    ->assertOk();

$this->fixtureTestimonial(TestFixturesSeeder::PENDING);
$this->fixtureAdmin();  $this->fixtureStranger();  $this->fixtureTranslator();
$this->fixtureInactiveSpace();  $this->fixtureForeignSpace();
$this->fixtureWidget();  $this->fixtureBadgeWidget();
```

Фабрики остаются для случаев, которым нужна запись, не покрытая фикстурами —
аккаунт без роли, третье пространство, разовый отзыв.

### Как добавить фикстуру

1. Добавьте константу и запись в `tests/Fixtures/TestFixturesSeeder.php`.
2. Если нужен помощник для поиска — расширьте
   `tests/Concerns/InteractsWithFixtures.php`.
3. Все тесты увидят её автоматически: сидер запускается в `setUp()`.

> Набор поднимает свежее приложение (и свежее соединение с базой) на каждый
> тест, поэтому полный прогон занимает около 35 секунд. Это цена работы против
> настоящего сервера PostgreSQL, а не файла SQLite в процессе.

## Заметки об архитектуре

**Почему и PHP, и Go?** Laravel ведёт кабинет, аутентификацию и CRUD. Go-сервис
отдаёт встраиваемый виджет и публичный API чтения — те профили трафика, где
маленький, быстрый, ничего не хранящий бинарник окупается.

**Почему роли *и* владение?** Владение — основная защита: пространство
принадлежит ровно одному аккаунту, и политика проверяет `user_id` первым. Роли
добавляют только то, что владение выразить не может, — надзор поверх аккаунтов.
Это оставляет общий случай быстрым (без обращения к правам), а
привилегированный — явным.

**Права.** Образ `app` создаёт пользователя, совпадающего с `APP_UID`/`APP_GID`
(значения берутся из `UID`/`GID`, по умолчанию `1000`), и запускает воркеры
PHP-FPM от его имени, поэтому всё, что пишет PHP — логи, скомпилированные
шаблоны, кеш — остаётся вашим, а смонтированные исходники остаются
редактируемыми. `storage/` и `bootstrap/cache` нуждаются только в `775`; они не
доступны на запись всем.

> Build-аргументы называются `APP_UID`/`APP_GID`, а не `UID`/`GID`, потому что
> последние — специальные переменные оболочки. Важнее другое: проверка, которая
> переключает пул, ищет пользователя **по имени**. busybox `id` не резолвит
> числовой uid, поэтому `id -u 1000` падает даже когда пользователь существует —
> и пул молча оставался на `www-data`, а все файлы, записанные PHP, принадлежали
> не тому пользователю.

Если файлы всё-таки оказались у `root` (например, после команды, запущенной от
root внутри контейнера), исправьте:

```bash
make fix-perms
```

**Тестовая база клонируется, а не мигрирует.** См. [Тестирование](#тестирование).

## Решение проблем

**`make: command not found`**
Установите `make` внутри WSL: `sudo apt update && sudo apt install make`.

**HTTP 500 и `tempnam(): file created in the system's temporary directory`**
PHP не может писать в `storage/framework/views`. Запустите `make fix-perms`.
Если не помогло — `make shell` и сравните `id` с `ls -ld /var/www/storage`.

**`Class "Predis\Client" not found`**
`REDIS_CLIENT` выставлен в `predis`, а пакета нет. В образе есть расширение
`phpredis`, поэтому поставьте `REDIS_CLIENT=phpredis` в `docker/.env` и
перезапустите: `make restart`.

**Отказано в доступе при правке файлов в `laravel/`**
Файлы создал root внутри контейнера. Запустите `make fix-perms`.

**Порт уже занят**
Поменяйте `APP_PORT` (или `DB_PORT`, `REDIS_PORT`) в `docker/.env`, затем
`make restart`.

**`TLS handshake timeout` при сборке из Docker Hub**
Временные проблемы сети до реестра. Повторите `make build` или настройте зеркало
реестра в Docker Desktop.

**502 после пересоздания контейнера**
nginx резолвит upstream один раз при старте и кеширует на весь срок жизни
процесса. В `nginx/default.conf` адрес вынесен в переменную и указан
`resolver 127.0.0.11`, поэтому пересоздание `app` больше не ломает сайт.

**Кнопки в интерфейсе показывают ключи вида `common.edit`**
Проп страницы перекрыл общий проп Inertia. См.
[Никогда не называйте проп страницы так же, как общий](#никогда-не-называйте-проп-страницы-так-же-как-общий).

**Сбросить всё, включая базу**

```bash
make down
docker compose --env-file .env-common down -v   # ⚠️ удаляет тома
make up && make migrate && make seed && make npm-build && make i18n
```
